# Release candidate architecture

2026-10-14. One production browser application: `apps/web`. The Asad, Umer and Wajahat workspace applications remain development/reference roots and are not production deployment artifacts. Deploy only `apps/web/dist`. `apps/web/src/main.tsx` mounts one React root; `providers/ApplicationProvider.tsx` wraps one shared AuthProvider. Feature modules reuse the host session, tenant and transport. Do not mount workspace providers inside host features.

The separate `wautech-crm/backend` application is the existing Java 25 / Spring Boot modular monolith. PostgreSQL is the system of record. Flyway V1–V24 evolves the existing schema; no separate business or AI database is introduced. Backend DTOs and authorization remain authoritative. Monetary values use exact decimal transport and currency-separated aggregates. Historical conversion and recognized revenue are unavailable.

Browser requests use same-origin `/api`; the reverse proxy forwards API paths to the backend and serves the SPA for browser routes only. Session cookies and a session-bound CSRF header protect writes. Backend authorization checks enabled users and persisted active membership for every tenant. Actual roles are OWNER, ADMIN, SALES_USER and VIEWER. MEMBER is not an alias. Tenant relationships use scoped queries and composite foreign keys. Frontend stale-response rejection protects organization changes; it is not a substitute for backend isolation.

AI tools are server-selected bounded read queries. The model cannot select arbitrary URLs, SQL, executable tools or CRM mutations. Provider output/source references are validated. Business context requires organization permission, private opt-in and per-question confirmation. User declarations, SQL facts and model hypotheses stay separate. Goal-to-task creation uses a five-minute session/user/tenant/version-bound preview and explicit confirmation through existing TaskService. Provider credentials remain server-side. AI conversation context expires after 20 minutes plus cleanup grace; previews after five minutes plus cleanup. Provider and backup retention need separate operational policy.

Deployment candidate is a single backend instance: HTTP-session conversations and sessions are not proven safe across multiple instances. Shared sessions, distributed scheduling, autoscaling and cloud infrastructure require an approved design. See [deployment](./deployment.md) and [release acceptance](./release-acceptance.md).
